---
title: Backend integration
description: Use the library directly from a Node backend.
---

InProduct is imported into your backend. It does not need a separate hosted server.
After [installation](/docs/installation), save this as `product.mjs` and run `node product.mjs`:

```js
import { slugify } from '@mp-lb/inproduct';

const createProduct = (name, existingSlugs) => {
  const slug = slugify(name);
  if (!slug) throw new Error('product name must produce a non-empty slug');
  if (existingSlugs.has(slug)) throw new Error('product slug already exists');
  return { name: name.trim(), slug };
};

console.log(createProduct('Everyday Mug', new Set()));
```

In a real API, validate input at your request boundary, use your application's error handling,
and enforce uniqueness transactionally in your own database. Authentication, storage, catalog,
cart and checkout are application responsibilities. This example's Set is not persistent storage.

## Repository backend

The private `apps/backend` health service and private core/server/tRPC packages are scaffold
infrastructure. They are not exported by `@mp-lb/inproduct`, and the library does not depend on them.
From a clone, `zap task setup` and `zap up backend` start the scaffold; use `zap status` to find
its allocated port. `GET /health` returns a greeting. It is not a MyShop commerce API.
