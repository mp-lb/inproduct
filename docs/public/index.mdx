---
title: InProduct
description: Small, composable tools that live inside your application.
---

InProduct puts reusable building blocks in the application that owns its data and workflows.
This is an early scaffold: the published library currently contains **one utility, `slugify`**.
Feature flags, audit logs, notifications, payments and commerce APIs are not implemented.

## Start small

- [Install the package](/docs/installation) and call it from your own code.
- [Initialize object storage](/docs/storage) with a memory, disk or MongoDB adapter.
- [Integrate with a backend](/docs/backend) without a hosted service or API key.
- [Run MyShop locally](/docs/myshop) to see a storefront and backend-powered file storage.

The library is `@mp-lb/inproduct`. The repository's `@mp-lb/inproduct-myshop-backend` package
is the private local demo backend, not a package to install in your app. Object storage is
a separate package, `@mp-lb/inproduct-storage`; it is not re-exported by `@mp-lb/inproduct`.

## Planned pieces

These modules are under development and are not exported by the current package.
The descriptions below are intended scope, not available APIs.

### Feature flags

Turn features on or off for specific users. No feature-flag API is available yet.

### Audit logs

Track who changed what, and when. No audit-log API is available yet.

### AI observability

Inspect AI requests, responses and costs. No AI-observability API is available yet.

### Notifications

Send and manage notifications from your app. No notification API is available yet.

### Prompts

Manage prompts as version-controlled Markdown. No prompt-management API is available yet.
