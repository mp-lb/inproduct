Software development has drifted toward platforms, dashboards and API keys. Every new capability seems to require another hosted service, another account, another billing relationship, and another admin interface. We believe many of these capabilities belong inside the application itself. Feature flags, audit logs, AI observability, notifications, prompts, and similar systems are not products in their own right for most teams—they are building blocks. They should feel like installing a package, not adopting a platform.

This project embraces a composable philosophy inspired by the best parts of Unix and early Rails. Each module should do one thing well, have clear boundaries, and compose naturally with the others. Instead of a monolithic framework, we provide small, opinionated components that can be adopted independently. Applications should be free to start with a single module and grow organically over time, without rewriting code or migrating between ecosystems. Sophisticated systems emerge from combining simple pieces, not from committing to an all-or-nothing platform.

We believe the application should own its own data, logic and user experience. Configuration lives alongside the code that uses it. Prompts belong in source-controlled Markdown files. Audit history belongs in your database. Observability belongs in your own admin interface. Rather than sending developers to another website to understand their own software, these modules bring operational capabilities directly into the application, integrating with the existing authentication, permissions and workflows that already exist.

Our goal is not to build another platform. Our goal is to restore software as a collection of reusable building blocks. Opinionated where it improves developer experience, modular where it enables flexibility, and simple enough that every piece can be understood on its own. Modern AI has made frontend development dramatically cheaper, shifting the real value back to backend architecture and business logic. This project is about making those backend capabilities easy to reuse across every application we build, allowing developers to spend less time rebuilding infrastructure and more time building products.
